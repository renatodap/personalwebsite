# Plate Sequence: rebuilding the site as a cyanotype plate book

**Date:** 2026-07-26
**Status:** approved, ready for implementation
**Supersedes:** `docs/superpowers/specs/2026-07-25-personal-site-redesign-design.md` and the Exploded Assembly world in full
**World contract:** `DESIGN.md`

---

## 1. Summary

The site is rebuilt as a vertical sequence of twelve frames followed by a close, each frame holding one or more of the twenty-three traced line drawings on a Prussian-blue field. The drafting conceit (bill of materials, callout balloons, item numbers, title block, revision table) is deleted entirely; the palette survives, reinterpreted as cyanotype rather than blueprint.

Renato's rejection was specific and is the origin of this work: *"i hate the bom design stuff. thats going too far."* The failure was that a visitor had to learn a notation before being allowed to look at anything. This design requires nothing of the visitor.

Deployment, host, database instance, ORM and domain configuration are unchanged. The database *schema* changes, because the old tables are shaped like a bill of materials.

**Success:** a visitor who leaves after five seconds knows he is a lead software engineer in Indianapolis. A visitor who reaches the end can describe him a week later without looking, and never read a sentence claiming he is interesting.

## 2. Scope

**In scope**

- Replace the public page with the thirteen-frame sequence.
- Replace the Prisma schema and seed with a frame model.
- New token set, one type family, two motions.
- Delete the retired component tree and the live-fitness-data path.
- Tests that mechanically enforce the copy and coverage rules.

**Out of scope**

- `/admin`. It does not exist yet and is not built here. The schema is shaped so it can be added without further migration.
- Live fitness data. Cut, per the storytelling research: a running total is a scoreboard, and scoreboards are banned in prose, so the ban extends to the page. `src/lib/activity.ts` is deleted.
- `/sheet/[slug]` detail routes. Never built; not built now. Every click is a chance to leave before the ending.
- Re-authoring or re-tracing drawings. All twenty-three ship as they are.

## 3. Data model

Same Postgres instance, same `DATABASE_URL`, same Prisma client, same `prisma db push` workflow already in `package.json`. The following replaces `Part`, `Detail`, `WorkNote` and `Revision`.

```prisma
enum FrameKind {
  PLATE  // one drawing, full height, snaps
  RUN    // three or four drawings sized by column width, ~78dvh, does not snap
  PAIR   // two drawings at equal weight, no caption, snaps
}

/// One frame of the sequence. Order is the argument, so order is data.
model Frame {
  id        String    @id @default(cuid())
  kind      FrameKind @default(PLATE)

  /// Blank is normal and expected: six of thirteen frames carry no words.
  /// Newline separates lines; the second and later lines render at --ink-70.
  caption   String    @default("") @db.Text

  sortOrder Int       @default(0)
  isActive  Boolean   @default(true)
  plates    Plate[]

  @@index([isActive, sortOrder])
}

/// One drawing inside a frame.
model Plate {
  id        String @id @default(cuid())
  frameId   String
  frame     Frame  @relation(fields: [frameId], references: [id], onDelete: Cascade)

  /// Slug only. Resolves to /drawings/detail-<drawing>.svg
  drawing   String

  /// Normalises figure height across traces. See DESIGN.md for the bands.
  /// Not polish: without it the small full-body figures look accidental.
  zoom      Float  @default(1)

  /// Accessible name. Required, because a mask-rendered drawing is a
  /// background and its SVG <title> is not exposed to assistive tech.
  alt       String @default("")

  sortOrder Int    @default(0)

  @@index([frameId, sortOrder])
}
```

`SiteSetting` is kept, with the drafting fields (`drawingTitle`, `sheetOf`, `subjectMode`) dropped and `subjectRole` / `subjectLocation` restated in sentence case rather than uppercase. `AdminUser` is kept untouched.

**Why two tables rather than a `String[]` column:** a frame holds one to four drawings and each needs its own `zoom` and `alt`. Arrays would make those positional and make a future admin form awkward.

**Why `kind` is explicit rather than derived from plate count:** a two-plate `RUN` (serve, tennis) and a two-plate `PAIR` (the wear frame) are different components with different scale, snapping and caption rules. Count cannot distinguish them.

**Whether a frame snaps is derived,** not stored: `kind !== RUN`. One less field to get wrong.

**Migration.** `prisma db push` drops the retired tables. Seeded content is regenerated by `prisma/seed.mjs`, rewritten to carry the full sequence below. No production content is at risk: there is no admin, so nothing has been authored through the app.

## 4. The sequence

**Twelve frames, then a close.** The close is not a `Frame` row and has no `FrameKind`: it is chrome rendered after the sequence, so the rail has twelve ticks, not thirteen. All twenty-three drawings, each used exactly once. Captions are final copy, subject to Renato's edit.

|---|---|---|---|

| 2 | RUN | `keys` `bass` `drums` `webcam-guitar` | I taught myself seven instruments the same way I learn everything else. By starting. |
| 3 | PLATE | `working` | A man asked me for a portfolio site. / What he actually needed was to stop running his company out of somebody else's spreadsheet. / Three weeks later the whole business ran on what I built. |
| 4 | RUN | `serve` `tennis` | Four years of college tennis. The last one as captain. |

| — | *close, not a Frame* | *(none)* | contact links |

Notes that are design decisions, not incidental ordering:

- **Frame 1 is the guitar, not the laptop.** The header already states engineer and Indianapolis, so the first *image* is free to break the category expectation rather than confirm it. This is the site's only real reversal and it is true.
- **Frame 2's run is the argument.** Four instruments in a row is what "seven" looks like; the caption states the method, the row supplies the evidence.
- **Frame 3 is the one place with three sentences.** It breaks the rhythm once, deliberately. It is the only but/therefore beat on the page and the only professional proof beyond the header.
- **Frame 6 is silent and is the peak.** Broken equipment says he goes hard enough to break things; laughing says he does not take it seriously. A caption would state the contradiction the images already are.
- **Frames 9 and 10 are a pair nobody had noticed:** the adult at Iguaçu, then the boy holding a Brazilian flag. Brazil to Indiana, no words.
- **Frame 11 establishes the rule three times.** Boy-with-guitar, boy-with-racket, boy-with-camcorder all arrive in slots the adult versions used, uncaptioned.
- **Frame 12 breaks it.** `peter-pan` has no adult counterpart, carries no caption, and nothing follows. The site never writes the sentence; the viewer writes it.

**Known tradeoff, accepted by Renato:** twelve frames plus the close is roughly ten to eleven screenfuls. The storytelling research argued for five to seven so the ending is reliably reached, and using all twenty-three drawings costs that. Mitigated by the last four frames being wordless and fast.

## 5. Component architecture

```
src/app/page.tsx              server; fetches, renders the sequence, JSON-LD
src/app/layout.tsx            fonts, metadata
src/app/globals.css           tokens, plate mechanics, the two motions
src/components/frame.tsx      server; PLATE | RUN | PAIR renderers
src/components/plate.tsx      server; the masked drawing, role="img"
src/components/chrome.tsx     server; Header, Close
src/components/rail.tsx       'use client'; the only JS on the page
src/lib/content.ts            getSettings, getFrames
src/lib/copy-guard.ts         extended: em-dash, banned register, throughput numbers
src/lib/db.ts                 unchanged
```

**Deleted:** `src/components/sheet/sections.tsx`, `src/components/drawing/parts.tsx`, `src/lib/tokens.ts`, `src/lib/activity.ts`.

Everything is a Server Component except `rail.tsx`. `page.tsx` keeps `export const revalidate = 900`.

**`plate.tsx`** renders a single div: `role="img"`, `aria-label={alt}`, inline `--z` and `mask-image` custom properties. No inline SVG anywhere; every drawing is a cached mask.

**`rail.tsx`** is a client leaf of about twenty lines. Ticks are real `<a href="#frame-n">` anchors, so navigation works with zero JS; a single `IntersectionObserver` sets the active tick. No scroll listener, no `requestAnimationFrame`, no state driven by scroll position.

## 6. Motion

Two motions, per `DESIGN.md`, both CSS, neither on the main thread.

```css
@media (prefers-reduced-motion: no-preference) {
  @supports (animation-timeline: view()) {
    /* 1. The plate develops. Exposure is the material's native behaviour. Once. */
    .develop { animation: develop 700ms cubic-bezier(0.23, 1, 0.32, 1) both; }
    @keyframes develop {
      from { clip-path: inset(0 0 100% 0); opacity: 0; }
      to   { clip-path: inset(0 0 0 0);   opacity: 1; }
    }

    /* 2. The frame advances. The blur is load-bearing: without it a crossfade
       between two line drawings reads as two objects overlapping. */
    .advance {
      animation: advance linear both;
      animation-timeline: view();
      animation-range: entry 8% cover 34%;
    }
    @keyframes advance {
      from { opacity: 0; filter: blur(2px); transform: scale(1.02); }
      to   { opacity: 1; filter: blur(0);   transform: scale(1); }
    }
  }
}
```

Scroll-snap on the container, `scroll-snap-align: start` on `PLATE` and `PAIR` frames only. `scroll-snap-type: y proximity`, not `mandatory` — mandatory fights the user on a long page and traps keyboard users between snap points.

Reduced motion and unsupported browsers get the settled state: a plain vertical sequence, fully legible, nothing hidden.

## 7. Accessibility

- Every plate has an `alt` rendered as `aria-label` on `role="img"`. A mask is a background; its SVG `<title>` is not exposed.
- Rail ticks are anchors with accessible names ("Frame 6 of 12" style, since the *number* may be announced even though it is never drawn), plus `aria-current` on the active one.
- `:focus-visible` is a 2px `--ink` outline at 3px offset. There is no accent colour to use instead.
- Contrast is measured, not assumed: `--ink` 12.8:1, `--ink-70` 7.0:1, `--ink-45` 3.75:1 and restricted to non-text. Recorded in `DESIGN.md`.
- Semantic structure: one `<h1>` carrying the name, `<figure>`/`<figcaption>` for captioned frames, `<main>`, `<nav>` for the rail.
- Keyboard: the page is a normal scroll document. Tab reaches the rail and the contact links. No focus trap, no scrolljacking.
- `100dvh` throughout, never `100vh`, so the iOS address bar does not cause a jump.

## 8. Performance

- Twenty-three masks is real rasterisation work. `content-visibility: auto` with `contain-intrinsic-size` on every frame so off-screen frames are not painted; without it first paint stalls on a mid-range phone.
- `contain: paint` on each plate, never `strict` (size containment collapses the aspect ratio).
- Total drawing payload is about 0.64 MB of SVG across all twenty-three, cached individually by the browser because they are `mask-image` URLs rather than inline markup.
- Archivo self-hosted via `next/font` with `display: swap`. No `<link>` to Google Fonts in production.
- Targets: LCP under 2.5s, CLS under 0.1 (every plate has an intrinsic square aspect ratio, so nothing reflows), INP under 200ms (there is almost no JS).

## 9. Testing

`vitest` is already configured. Tests encode the rules that would otherwise drift:

1. **Coverage.** Every one of the twenty-three files in `public/drawings/` appears exactly once across the seeded sequence. This is Renato's instruction ("use as many of the svg renderings as possible") turned into a failing test if a drawing is dropped.
2. **Resolution.** Every `drawing` slug in the seed resolves to a file that exists on disk.
3. **Copy guard.** No visible string contains an em-dash or en-dash, any banned-register phrase, or a client/company/product name. Runs over captions and every `SiteSetting` string.
4. **Throughput numbers.** No caption contains a count of applications, clients, servers or repositories.
5. **Zoom bounds.** Every `zoom` is between 1.0 and 1.8; a value outside that is a data error, not a taste choice.
6. **Kind and plate count agree.** `PLATE` has one plate, `PAIR` has two, `RUN` has two to four.

## 10. Deployment constraints, unchanged and binding

- Coolify on the existing Hetzner box, one shared Postgres instance.
- Deployed at the **root domain**, so no `basePath`.
- The deployment carries **hand-edited Traefik labels** implementing the `www` to bare-domain redirect for every other app on that server. **Any redeploy or config change must preserve them.** This is the single highest-consequence constraint in the build.
- `npm run build` already runs `prisma generate` first. Unchanged.

## 12. Open decisions

1. **Captions are draft copy.** Every string in section 4 is mine, written in his register from confirmed source material. He should edit them; nothing in the build depends on the exact wording.
2. **Frame 3's client story is anonymous by rule but unverified in phrasing.** "Somebody else's spreadsheet" and "three weeks" are mechanism, not party, so they satisfy the anonymity constraint. `PRODUCT.md` still flags "confirm before shipping any case description" as inferred; that confirmation has not happened.
3. **`falls` is assumed to be Iguaçu.** The pairing of frames 9 and 10 rests on it being Brazil. If it is another waterfall the pair still reads as travel but loses the Brazil-to-Indiana reading.
4. **Whether the header should also carry a contact link.** Currently contact lives only at frame 13, which a visitor who leaves early never reaches. Left out for now on restraint grounds; worth revisiting after the five-person test.

## 13. Changed during implementation

This spec was written before the build. Everything below diverged from it, on purpose; sections above are left as written so the reasoning is auditable, and this is the authoritative list of where they are now stale.

**Cropping is banned, and `zoom` is gone entirely** *(§3, §9, and the plate bands in DESIGN.md)*. Renato's instruction on 2026-07-26: "make sure no svg renderings crop." The spec's `zoom Float` field normalised figure size by scaling the mask past its box and letting the surplus fall outside, which is cropping by construction. Replaced by `scripts/tighten_viewbox.mjs`, which trims each drawing's viewBox to its own artwork so `mask-size: contain` alone gives consistent figure heights. The `Plate` model has no size field, the components take no size prop, and a test asserts the data carries none. Consequently §3's stated reason for two tables is now half void: the relation exists for `alt` and `sortOrder`, not for per-plate zoom.

**Two captions were cut, so eight of twelve frames are silent, not six** *(§4)*. Frame 3's client story was removed at Renato's instruction. Frame 7's line ("I like the part that doesn't work yet") was removed after he asked what it was supposed to mean, which is the only review that matters; it was a compression of his own "the messy middle" and it compressed past legibility. He then chose to leave frame 7 silent rather than replace it.

**There is now no professional proof beyond the header role line.** §4 called frame 3 "the only professional proof beyond the header," and it is gone. This is Renato's explicit call and the site is a calling card with no conversion event, but it is the single biggest deliberate omission and is recorded as such.

**Runs are `70dvh`, not `78dvh`** *(§3, §4)*, and their column cap scales with plate count (430px at two, 350px at three, 300px at four). A two-plate run at the four-plate cap left its plates stranded in an empty row.

**`content-visibility: auto` was removed, not required** *(§8)*. It paints skipped subtrees as bare ground, which on a page made entirely of images means blank screens. The assumption that 23 masks would stall first paint was inherited from the retired design, which put many drawings on screen at once; this one shows at most four per frame.

**`scroll-behavior: smooth` was added and then removed.** It is a third motion, which this world does not have, and it broke the rail: smooth-scrolling the full page height means the visitor rides through every intervening frame instead of arriving.

**The copy guard moved** *(§5)*. `src/lib/copy-guard.ts` is deleted. The rules live in `prisma/copy-rules.mjs`, shared by the seed and the tests, so there is one implementation instead of a TypeScript copy plus an inline duplicate in the seed that had already drifted.

**DOM order is plate then caption** *(§11)*. The spec claimed the caption precedes the plate. It does not: `figure` takes its `figcaption` last, and both breakpoints place the caption with explicit grid rows, so layout never depends on source order.

**`getSettings()` reads instead of upserting.** An upsert meant a GET wrote to the database on every render and revalidation, and would fail outright against a read-only connection.

**The pacing tradeoff is worse than §4 estimated.** §4 said the length cost was "mitigated by the last four frames being wordless and fast." Measured, frames 9 through 12 are about a third of the page and contain its three largest images, so the tail is the slowest stretch, not the fastest. Recorded rather than fixed: see the open pacing question below.
